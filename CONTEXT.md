# Family Minecraft operations

Operate one `family` server instance for six family players using Java and Bedrock clients, with full infrastructure provisioning, persistent data, and verified recovery. On October 10, 2026, Craig chose to rebuild on Crafty Controller and Multiverse ([ADR 0004](docs/adr/0004-crafty-multiverse-rebuild.md)): one Paper server holds the `survival` and `creative` worlds, linked by portals, behind one join address. The instance owns one server folder, one pair of ports, one backup namespace and one lifecycle. The earlier independent `survival` and `creative` instances, described in the dated records below, are superseded and their test worlds were not kept.

On October 3, 2026, Craig accepted the connected clients and waived requirements or validations involving consoles or family-member testing. Reported joins were Java on Mac, Bedrock on iPhone and two iPads, with four simultaneous players. PS5/Switch were untested and BedrockConnect was never configured; console guidance remains optional future help. Family-device acceptance is resolved by user acceptance/waiver, with unperformed checks recorded as unperformed rather than passed.

This acceptance does not replace [#8's live recovery proof](https://github.com/CraigDevJohnson/minecraft/issues/8) or [#26](https://github.com/CraigDevJohnson/minecraft/issues/26)/[#27](https://github.com/CraigDevJohnson/minecraft/issues/27)'s upstream, runtime, infrastructure and technical protocol safety gates.

Craig also removed recovery authorization and maintenance windows and overall recovery time ceilings on October 3, 2026: approved recovery work continues without renewing permission because time elapsed, and actual durations are recorded. Command execution timeouts, the 15-minute fresh-disk provenance check before a zero-fill ([infrastructure operations](docs/operations/infrastructure.md)), write safety and source integrity remain in force.

## Terms

- **Host:** the replaceable EC2 machine. Its running/stopped state controls compute billing.
- **Endpoint:** the DNS hostname players use to reach the host. Its IPv4 address changes on every host start and is parked on a never-routed address while the host is stopped.
- **Server instance:** one independently configured Minecraft runtime and content set. The only one is `family`, run by Crafty Controller. It owns its server folder, ports, backup namespace, and lifecycle.
- **World:** a playable map within an instance. `family` holds two Multiverse worlds, `survival` (with its Nether and End) and `creative`, each with its own inventories. Worlds share the instance's ports, archive and lifecycle.
- **Crafty Controller:** the process manager on the host, with an admin web UI and API on loopback only. It alone starts and stops the server; the lifecycle adapter asks it to through its loopback API, and sends console commands the same way from a Session Manager shell.
- **Launcher:** the backend of The Lobby's Minecraft Launcher page, a Lambda in `lambda/launcher`, and the one operator of the server. It reports the server's state, starts the host and game the way the workstation start did, stops them the way the workstation stop did, restores an archive into the stopped server, and changes the allowlist. The page, the Server control workflow and `task server:*` only ask it; nothing runs on a workstation ([ADR 0006](docs/adr/0006-cloud-controls.md)). See the [launcher runbook](docs/operations/launcher.md) and [cloud controls](docs/operations/cloud-controls.md).
- **Archive:** one stopped-server folder stored in S3 on every stop, with its SHA-256. It is the recovery point for the `family` instance.
- **Content manifest:** the exact runtime, plugins/mods, resource packs, mappings, versions, and integrity metadata needed to recreate an instance. For `family` it is `runtime/crafty/server.json`, which the launcher carries and every start applies to the stopped server ([ADR 0008](docs/adr/0008-the-adapter-applies-the-pinned-server-content.md)).
- **Bedrock transport:** how Bedrock clients reach Geyser on port 19132. RakNet uses UDP 19132; NetherNet uses Geyser's built-in signaling on TCP 19132 and WebRTC on UDP 19133. `family` serves both, and Bedrock 26.60 clients use NetherNet only.
- **Recovery point:** a verified, completed backup of the data and content configuration needed to recover an instance.

The [server design](docs/superpowers/specs/2026-09-07-server-operations-design.md) records shared requirements; [ADR 0001](docs/adr/0001-independent-server-instances.md) records the earlier runtime boundary that [ADR 0004](docs/adr/0004-crafty-multiverse-rebuild.md) supersedes, [ADR 0002](docs/adr/0002-dynamic-public-ipv4-with-cloudflare-hostname.md) the endpoint, [ADR 0005](docs/adr/0005-lobby-launcher-starts-from-aws.md) the Lobby Launcher's starts from AWS, and [ADR 0006](docs/adr/0006-cloud-controls.md) the stop, the allowlist and the deploys from the cloud.
