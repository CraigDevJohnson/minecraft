# Family Minecraft operations

Operate the family's Minecraft worlds for six family players using Java and Bedrock clients, with full infrastructure provisioning, persistent data, and verified recovery. On November 10, 2026, Craig chose one host per world ([ADR 0009](docs/adr/0009-one-host-per-world.md)): `survival`, `creative` and `adventure` each run on an EC2 host of their own, with their own mods, address, archives and lifecycle, and all three start fresh. That replaces the October 10, 2026 rebuild on Crafty Controller and Multiverse ([ADR 0004](docs/adr/0004-crafty-multiverse-rebuild.md)), where one `family` server held the `survival` and `creative` worlds, linked by portals, behind one join address. Crafty, the stop archive and the cloud controls carry over. The family host was removed from the configuration on November 11, 2026, and is retired by the Deploy the [worlds runbook](docs/operations/worlds.md#the-family-hosts-retirement) describes; its archives stay under `instances/family/crafty/`. The earlier independent `survival` and `creative` instances of ADR 0001, described in the dated records below, were superseded on October 10 and their test worlds were not kept.

On October 3, 2026, Craig accepted the connected clients and waived requirements or validations involving consoles or family-member testing. Reported joins were Java on Mac, Bedrock on iPhone and two iPads, with four simultaneous players. PS5/Switch were untested and BedrockConnect was never configured; console guidance remains optional future help. Family-device acceptance is resolved by user acceptance/waiver, with unperformed checks recorded as unperformed rather than passed.

This acceptance does not replace [#8's live recovery proof](https://github.com/CraigDevJohnson/minecraft/issues/8) or [#26](https://github.com/CraigDevJohnson/minecraft/issues/26)/[#27](https://github.com/CraigDevJohnson/minecraft/issues/27)'s upstream, runtime, infrastructure and technical protocol safety gates.

Craig also removed recovery authorization and maintenance windows and overall recovery time ceilings on October 3, 2026: approved recovery work continues without renewing permission because time elapsed, and actual durations are recorded. Command execution timeouts, write safety and source integrity remain in force. The 15-minute fresh-disk provenance check before a zero-fill went with the family host's data disk.

## Terms

- **World:** one playable map with its own server, mods and players' inventories: `survival`, `creative` or `adventure`. The pinned content lists the worlds in display order, and the first is the one a request that names no world means. A world's id also names its instance, its archive prefix and the first label of its address.
- **World host:** the replaceable EC2 machine that runs one world. Its running/stopped state controls compute billing. The world lives on its root disk, and a new or replaced host sets itself up and restores the newest archive at its world's first start.
- **Family host:** the single host of [ADR 0004](docs/adr/0004-crafty-multiverse-rebuild.md), with its retained data disk and the `family` instance. Removed from the configuration on November 11, 2026, with its data disk and its by-hand tooling, and retired by the Deploy the [worlds runbook](docs/operations/worlds.md#the-family-hosts-retirement) describes; its archives stay in the backup bucket.
- **Endpoint:** the DNS hostname players use to reach a world, `<world>.<the public hostname>`. Its IPv4 address changes on every start of that world's host and is parked on a never-routed address while the host is stopped.
- **Server instance:** one independently configured Minecraft runtime and content set, run by Crafty Controller. Each world host runs exactly one, named by its world's id. It owns its server folder, ports, backup namespace, and lifecycle.
- **Loader:** the mod loader a world's server runs: Fabric for `survival` and `creative`, NeoForge for `adventure`. The content manifest pins what each loader's server starts from.
- **Mod:** a Fabric or NeoForge mod the content manifest pins by URL and SHA-256 in its catalog, with the loaders it runs on. Each world lists the mods it may run, each on or off by default.
- **Mod switch:** a Member's choice to run a world with a mod set differently from its default. The Launcher keeps only the switches (the code calls them switches; the parameter is `/<prefix>/launcher/mods`), and a switch applies at that world's next start.
- **Allowlist of record:** the family's one list of admitted players, kept by the Launcher in `/<prefix>/launcher/allowlist`. Every start writes it over that world's `whitelist.json`, and a change also reaches each running world.
- **Crafty Controller:** the process manager on each world host, with an admin web UI and API on loopback only. It alone starts and stops the server; the lifecycle adapter asks it to through its loopback API, and sends console commands the same way from a Session Manager shell.
- **Launcher:** the backend of The Lobby's Minecraft Launcher page, a Lambda in `lambda/launcher`, and the one operator of the worlds. It reports each world's state, starts and stops a world's host and game, restores an archive into a stopped world, switches mods, and changes the allowlist. The page, the Server control workflow and `task server:*` only ask it; nothing runs on a workstation ([ADR 0006](docs/adr/0006-cloud-controls.md)). See the [launcher runbook](docs/operations/launcher.md) and [cloud controls](docs/operations/cloud-controls.md).
- **Archive:** one stopped-server folder stored in S3 on every stop, with its SHA-256, under `instances/<world>/crafty/`. It is the recovery point for that world, and the only copy that outlives its host.
- **Content manifest:** the exact runtime, plugins/mods, resource packs, mappings, versions, and integrity metadata needed to recreate a world's server. It is `runtime/crafty/server.json`: a base every world shares, the catalog of mods, and the worlds. The launcher carries it and every start applies it to the stopped server ([ADR 0008](docs/adr/0008-the-adapter-applies-the-pinned-server-content.md)).
- **Bedrock transport:** how Bedrock clients reach Geyser on port 19132. RakNet uses UDP 19132; NetherNet uses Geyser's built-in signaling on TCP 19132 and WebRTC on UDP 19133. Every world serves both, and Bedrock 26.60 clients use NetherNet only.
- **Recovery point:** a verified, completed backup of the data and content configuration needed to recover a world.
