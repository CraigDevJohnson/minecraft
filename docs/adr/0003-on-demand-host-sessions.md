# ADR 0003: Operator-owned on-demand host sessions

Status: Superseded by [ADR 0004](0004-crafty-multiverse-rebuild.md), which on 2026-10-10 kept the world on a retained disk. Accepted design, 2026-10-03. Phase-one live acceptance completed on 2026-10-05, and #23 is closed. Phase-two migration, protection, and actual off state were verified; cold recovery and failure/resume proof were abandoned, and #24 closed as superseded on 2026-10-16. Retiring its code is #70.

Craig approved the two-phase on-demand design for #23/#24. In phase one, `on-demand-host` removes the replaceable host and root after a verified drain and confirmed graceful EC2 stop for safe detach, retaining the independently protected data disk. Operator start recreates the host through the existing OpenTofu root. Network, host role/profile, backups, budget and state remain outside the session lifecycle. The default `retained-host` behavior stays compatible. An absent host is a valid version-2 handoff only in the opt-in mode.

Use the reviewed Ubuntu ARM64 AMI and automate the existing prerequisites/runtime installers. Pin a deterministic, credential-free runtime archive by SHA-256 under `bootstrap/releases/<digest>/runtime.tar.gz` in the private backup bucket. The host reads only that immutable release prefix. Introduce an image build only if measured startup requires it. The initial provisional target was 180 seconds from operator start through endpoint/game readiness. On October 5, Survival reached controller readiness in 158.700 seconds and both worlds in 232.909 seconds. Automatic DNS and independent external Java and Bedrock checks passed. Craig accepted the measured 3-minute-53-second result without changing the AMI or adding resources. The accepted result exceeds the provisional target.

The designated workstation owns one lock across drain, plan/apply, handoff, private setup, game readiness and DNS. Its private journal binds account, profile, backend lineage/serial, source/input/release digests and exact resource inventory. Actual saved plans may only create or delete the session host and its orderly attachment; a partial apply can regenerate only the independently verified remaining changes in that same operation. Unexpected ownership, changed protected resources, replacement/update actions, drift, deferred changes and changed inputs refuse execution.

Deployment, operator configuration and the RCON secret remain owner-only local files and root-owned mode-0600 installed files. Transfer them through an SSM loopback port-forwarding session to a bounded single-use digest-bound receiver with a fixed allowlist. Payload bytes never enter Run Command, user data, Terraform values, the runtime archive or diagnostic output. The operator remains required to recreate a host. Headless operation is a separate credential-path decision.

Reject the existing `idle_stop` integration with on-demand mode because it binds permissions and environment to one host ID. The data-volume removal phase (#24) needs its own protection/ownership migration and independently verified durable versioned S3 recovery receipt before deletion; phase one keeps `aws_ebs_volume.data[0].prevent_destroy` unchanged.

This extends ADR 0001's replaceable-host boundary and preserves ADR 0002's DNS-only endpoint. Neither an offline passing test nor a merged PR establishes no-host/root live proof or startup timing. See [the operator workflow](../operations/on-demand-host.md).

The second opt-in `s3-only` phase uses a separate session data-volume address after an explicit reviewed no-change ownership/protection migration. Before deletion, the designated operator independently verifies and protects exact recovery versions, advances a durable selection and preserves latest fourteen/current/active points. Start requires receipt-bound capacity/new UUID, successful-apply provenance including the unchanged 900-second wait, historical completed-marker version scan, and full exact restore before play. Partial/uncertain targets stay stopped for repair; phase-two timing has no 180-second claim. See [S3-only world operations](../operations/s3-only-world.md).

On October 5, the four Stage A policy updates, actual host historical-version reads, compatible runtime installation, and trusted private configuration passed verification. The original encrypted 5 GiB disk moved to the session data address without a physical change. A full plan with no managed resource actions published the actual session-owned handoff, followed by secure installed configuration and certificate verification. Protection proof covers 20 frozen legacy points and two genuine final-session receipts, with the original recovery versions preserved.

The normal S3-only stop then removed the recorded host, root, and session data EBS disks. Independent AWS reads and the authoritative receipt/checkpoint baseline proved the off state. DNS parking remains pending.

The cold trial found workstation boundary defects in UUID CLI encoding, GP3 created-default matching, and the zero-fill filesystem UUID argument. PRs #48, #49, and #50 fixed those defects and merged with passing CI. The same new host, encrypted 4 GiB disk, target UUID, and receipts remain preserved. An actual 906-second provenance wait passed before the zero-fill parser refused the incomplete command without disk writes. The disk remains unformatted and games have not started. Corrected initialization and restore await source-profile sign-in, while DNS repair awaits password-manager access. The expired provenance proof remains historical; the unchanged native fresh 900-second check is still required. Recovery authorization windows and overall time ceilings remain removed. Cold recovery and actual failure/resume evidence remain pending.
