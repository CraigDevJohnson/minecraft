# Instance allowlist changes

From anywhere, add or remove a player with the [Server control workflow](cloud-controls.md#the-server-control-workflow) (`allowlist-add` or `allowlist-remove` with the edition and the name) or `task server:allowlist OP=add EDITION=java PLAYER=<name>`. Both ask the [launcher](launcher.md#allowlist-changes), which looks the player up and runs the host command below on the live server; nothing runs where you run it. The rest of this page describes that host command, for the launcher's benefit and for a hands-on emergency.

The host command is the Crafty adapter's `allowlist` action. It needs the configured instance (`family`) running with its Java port answering, holds the adapter's lifecycle lock, and refuses while the host is draining. The launcher installs the adapter it carries before it runs this command, so the host always has the version the launcher was deployed with ([ADR 0007](../adr/0007-the-launcher-carries-the-host-adapter.md)). The archive taken at the next stop includes `whitelist.json` with the rest of the server folder.

Provide one player's verified identity in a private JSON file owned by the user running the command, with mode `0600`. The object has `uuid` and `name` fields: use the actual server UUID in canonical lowercase hyphenated form, and the verified Java account name or unprefixed Bedrock gamertag. The file must refer to the same account in both fields. Identity verification remains required for each access change; test fixtures do not establish those identities. Craig resolved the console and family testing requirements on 2026-10-03; see the [current acceptance record](family-device-validation.md).

```sh
sudo /usr/local/sbin/minecraft-instance --config /etc/minecraft/operator.json allowlist family add --edition java --player-file /private/java-player.json
sudo /usr/local/sbin/minecraft-instance --config /etc/minecraft/operator.json allowlist family add --edition bedrock --player-file /private/bedrock-player.json
sudo /usr/local/sbin/minecraft-instance --config /etc/minecraft/operator.json allowlist family remove --edition bedrock --player-file /private/bedrock-player.json
```

The adapter sends each console command through Crafty's API (`POST /api/v2/servers/<id>/stdin`), because the server has RCON off. Crafty writes every console command, with the name in it, to its audit log on the data disk and to its container log under `/var/lib/docker` on the encrypted root disk, and the game writes the change to `logs/latest.log`. None of them leaves the host.

Java changes use the server's `whitelist add/remove` command. This operator interface accepts 3–16 ASCII letters, digits, and underscores for Java names. Bedrock changes use Floodgate's `fwhitelist add/remove` command with the gamertag, without the configured Floodgate username prefix. The [Floodgate documentation](https://geysermc.org/wiki/floodgate/features/) defines that command routing.

For Bedrock, this interface accepts Unicode letters/numbers, ASCII spaces, and underscores, with no leading/trailing spaces and at most 16 UTF-16 units. Tags containing spaces are passed as one quoted argument. Quotes, backslashes, control characters, and command punctuation are rejected. Floodgate build 141's [argument parser](https://github.com/GeyserMC/Floodgate/blob/81b65ccb766bf8024858ebf3eefa6974056aecc5/core/src/main/java/org/geysermc/floodgate/player/audience/PlayerAudienceArgument.java) supports quoted names and uses the same length boundary. Its source is unchanged from build 140; build 141 changes only the cloud command-framework dependency, from 2.0.0-beta.16 to 2.0.1. Passing this syntax check does not verify an Xbox account or its UUID.

The operation reads the server's `whitelist.json` before sending a command. If the supplied UUID already has the requested membership, it returns `allowlist: unchanged` without sending anything. Otherwise it sends one command and polls `whitelist.json` for up to 60 seconds until that exact UUID is present for add, or absent for remove. It reports `allowlist: updated` only after observing the requested membership. Invalid or duplicate UUID entries prevent verified completion.

Floodgate's [whitelist implementation](https://github.com/GeyserMC/Floodgate/blob/81b65ccb766bf8024858ebf3eefa6974056aecc5/core/src/main/java/org/geysermc/floodgate/command/WhitelistCommand.java) can resolve gamertags asynchronously, and Crafty's API answers only that it passed the line to the console, so only the file establishes completion. A lookup failure, missing change, or mismatched UUID reaches a bounded failure. A command may have changed access or may still be completing when verification fails; inspect private server state and correct the identity or lookup problem before retrying. Repeating the same request verifies current state and avoids repeating a completed change.

A Java account that was renamed, or deleted, no longer resolves to a UUID, though the allowlist may still hold it under its old name. For a Java removal only, the player file may hold the name alone, `{"name": "<JavaName>"}`. The adapter then removes the one entry with that name, ignoring case, by rewriting `whitelist.json` in place (same owner and mode) and running `whitelist reload`, and answers `updated`. It answers `allowlist: not-listed` when no entry has that name and refuses when more than one does. The launcher sends a name alone only when Mojang does not know the name.

Successful output contains only the instance ID, edition, operation, and `updated`, `unchanged` or `not-listed` result. Failures print one fixed diagnostic as `{"error": ...}`. UUIDs, names, console responses, and allowlist contents never reach the output. These commands do not disable the allowlist, change online authentication or assign operator privileges. Access removal changes allowlist membership; it does not promise immediate disconnection of an already-connected player.

`tests/test_minecraft_access.py` exercises the shared module through a controlled console and private-file boundary: routing, quoted Unicode Bedrock tags, eventual completion, duplicate operations, exact UUID matching, failed lookup/removal, malformed files, private-output handling, and command-injection rejection. `tests/test_minecraft_crafty.py` runs the adapter's action against a fake Crafty API and server folder, including the removal by name, the player file's checks and the command line the launcher sends. These fixtures use made-up players, and do not contact identity services or connect family devices.
